# FERN — Non-Technical Content Administration

15 September 2026. Required production capability; not implemented in the current reader-facing prototype. Canonical requirements: website PRD v1.12, CMS-04–09.

### Content Editing for Non-Technical Administrators

**CMS-04 · P1 — Everyday editing without engineering:** Authorised administrative staff must be able to maintain routine FERN website content without writing code, editing HTML, Markdown or JSON, using Git, running a build or asking an engineer to publish each change. Provide an Amazon-approved visual CMS interface with plain-language labels, short instructions and examples. Content administration is a release requirement for the managed website, not an optional future enhancement.

**CMS-05 · P1 — Clear content controls:** Start from a searchable page/content list showing title, section, owner, status and last update. Let staff edit page headings, paragraphs, approved lists, help information, authorised contact details, homepage summaries and learning introductions. Provide a reusable media library with upload/replace, image preview, crop/focal-point controls and an alternative-text field. Let authorised editors manage navigation labels, links and ordering within agreed structures. Keep reusable content in one record so the same introduction or contact does not need updating on several pages.

**CMS-06 · P1 — Templates that protect the design:** Provide approved page and section templates that retain FERN colours, typography, spacing, responsive layout and accessible heading structure. Staff can add or reorder supported content blocks within those templates. They must not need to resize layouts manually or edit CSS. Clearly explain required fields, broken links and unsupported file types next to the affected field. Application calculations, access rules and integration settings are not ordinary content-editing controls.

**CMS-07 · P1 — A simple, recoverable workflow:** Use the sequence Find the page → Edit → Save draft → Preview → Submit for review → Publish. Show whether changes are saved and whether the user is editing a draft or the published version. Autosave drafts with clear saved/error states and recovery; saving must not publish. Preserve the existing published page if saving or publication fails. Provide desktop and mobile previews, a readable before/after comparison, version history and restoration of an earlier version as a new draft subject to the normal approval process. Detect concurrent edits and help users resolve them without silently overwriting another person's work.

**CMS-08 · P1 — Authorised publication and source protection:** Authors prepare content; designated reviewers check it; authorised publishers release or withdraw it. Amazon determines whether people may hold more than one role. An editor without publishing permission cannot bypass review. Provide a clearly labelled Manage Content entry only to authorised staff, using Amazon identity and CMS permissions. Protect verbatim BBM/ISO source content from ordinary copy editing: maintain it through a controlled source-replacement/import process, preserving editions, identifiers, original files and specialist review. CMS edits to explanatory guidance must remain distinct from changes to an authoritative standard. Learning introductions may be edited here; courses, assessments and learner records remain governed by the approved LMS.

**CMS-09 · P1 — Demonstrate usability with admin staff:** Before acceptance, at least three representative non-technical administrators must independently complete the appropriate tasks after a short orientation: find and change a paragraph, replace an image and add alternative text, update an authorised contact or link, preview a page on desktop/mobile and submit it for review. An authorised publisher must publish the reviewed change; staff must also find version history and restore an earlier revision through the approval workflow. No coding, repository access or engineering intervention is allowed for these tasks. Verify unauthorised publication is blocked, drafts stay private, failed saves retain recoverable edits, and the published change and its withdrawal reach website/search within the agreed synchronisation window. Record task outcomes, confusion and errors; resolve blocking usability issues before release.

**Engineering and handover:** Amazon identifies the approved CMS, content owner, editor/reviewer/publisher roles, service contacts and support arrangements. Hein Consulting supplies the content model, templates, field definitions, workflow requirements and acceptance scenarios. Amazon engineering implements the CMS connection, identity, media handling, preview and publication behaviour. Provide administrators with a short illustrated guide and a supported help route. Confirm editing on standard desktop browsers and tablets, with keyboard access and no hover-only controls; full phone-based authoring is not assumed.

**Current capability:** The present website and standalone HTML are reader-facing prototypes. They do not yet provide this connected administrator editing and publication interface. Ordinary content remains in source components/data until the approved CMS integration is implemented. An edit in a browser or downloaded HTML must not be described as a shared published update.
